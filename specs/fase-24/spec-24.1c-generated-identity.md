# Spec: GENERATED ALWAYS AS IDENTITY

Phase: 24 — Complete Type System
Task: 24.1c — SQL-standard identity columns
Status: approved

## Context

AxiomDB already supports `AUTO_INCREMENT` / `SERIAL` / `BIGSERIAL` (Phase 24.1/24.1b):
the catalog stores `auto_increment: bool` (flags bit1 in `ColumnDef`) and `assign_auto_increment`
in `insert_helpers.rs` generates sequence values. `GENERATED ALWAYS AS (expr)` computed columns
also exist (Phase 21.5f). This subphase adds `GENERATED ALWAYS AS IDENTITY` and
`GENERATED BY DEFAULT AS IDENTITY` — the SQL:2003 standard syntax for auto-incrementing columns
with enforcement semantics. PostgreSQL calls these "identity columns" (`pg_attribute.attidentity`).

## Goal

Parse `GENERATED ALWAYS|BY DEFAULT AS IDENTITY` column syntax, persist the identity kind in the
catalog, and enforce the semantics at INSERT time: ALWAYS columns reject explicit values;
BY DEFAULT columns accept them.

## Non-goals

- `OVERRIDING SYSTEM VALUE` / `OVERRIDING USER VALUE` clauses in INSERT — deferred
- Identity sequence options: `START WITH`, `INCREMENT BY`, `MINVALUE`, `MAXVALUE`, `CYCLE`,
  `CACHE` — parsed and ignored (silently accepted); sequence always starts at max+1 with step 1
- Identity column `ALTER TABLE` operations (`ADD GENERATED`, `DROP IDENTITY`) — deferred
- UPDATE enforcement for ALWAYS columns (PostgreSQL disallows explicit UPDATE too) — deferred
- MERGE / ON CONFLICT identity enforcement — deferred

## Behavior

### Syntax accepted

```sql
-- GENERATED ALWAYS AS IDENTITY (no explicit INSERT allowed)
CREATE TABLE t (
    id   INT  GENERATED ALWAYS AS IDENTITY,
    name TEXT
);

-- GENERATED BY DEFAULT AS IDENTITY (explicit INSERT allowed)
CREATE TABLE t (
    id   BIGINT GENERATED BY DEFAULT AS IDENTITY,
    name TEXT
);

-- Options clause: parsed, values ignored, sequence still starts at max+1 with step 1
CREATE TABLE t (
    id INT GENERATED ALWAYS AS IDENTITY (START WITH 100 INCREMENT BY 5)
);
```

### Semantics

**GENERATED ALWAYS AS IDENTITY** (`identity_kind = IdentityKind::Always`):
- Column is implicitly `NOT NULL` and `auto_increment = true`.
- INSERT: if the user supplies a non-NULL, non-zero explicit value → `DbError::InvalidValue`.
- INSERT: if user omits the column, or supplies `NULL` or `0` → sequence value assigned (same as AUTO_INCREMENT).
- INSERT INTO t(other_col) VALUES (...) → id gets auto-generated value.
- INSERT INTO t VALUES (5, 'x') → error: cannot insert into ALWAYS identity column.

**GENERATED BY DEFAULT AS IDENTITY** (`identity_kind = IdentityKind::ByDefault`):
- Column is implicitly `NOT NULL` and `auto_increment = true`.
- INSERT: explicit value accepted and stored as-is.
- INSERT: NULL or 0 → sequence value assigned.
- Behavior is identical to `AUTO_INCREMENT` / `SERIAL` at runtime.

**Backward compatibility with existing AUTO_INCREMENT:**
- Old tables: `auto_increment = true`, `identity_kind = IdentityKind::None` (trailing byte absent → defaults to 0 = None).
- All existing behavior unchanged.

### Error cases

| Condition | Error | Message |
|-----------|-------|---------|
| `INSERT INTO always_col_table VALUES (5, ...)` | `DbError::InvalidValue` | `"cannot insert explicit value into column '{name}': column is GENERATED ALWAYS AS IDENTITY"` |
| `GENERATED foo AS IDENTITY` | `DbError::ParseError` | `"expected ALWAYS or BY DEFAULT after GENERATED"` |
| `GENERATED ALWAYS AS` then unexpected token | `DbError::ParseError` | `"expected '(' for expression or IDENTITY"` |

### SHOW COLUMNS display

`Extra` column:

| `identity_kind` | `auto_increment` | Displayed Extra |
|-----------------|------------------|-----------------|
| `None` | `true` | `auto_increment` |
| `Always` | `true` | `GENERATED ALWAYS AS IDENTITY` |
| `ByDefault` | `true` | `GENERATED BY DEFAULT AS IDENTITY` |

### SHOW CREATE TABLE display

```sql
-- ALWAYS:
`id` int NOT NULL GENERATED ALWAYS AS IDENTITY,

-- BY DEFAULT:
`id` bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
```

## On-disk format

New trailing byte appended to `ColumnDef` binary encoding (after the existing `array_element_type`
byte when `array_ndims > 0`, or directly after `enum_type_name` when ndims = 0):

```
offset  size  field         description
  ...   existing ColumnDef fields ...
  +0    1     identity_kind  0x00=None, 0x01=Always, 0x02=ByDefault
```

This byte is only written when `identity_kind != None` (the field is truly optional; old readers
stop before it and see `None` = 0x00 by default). New readers: if bytes remain past `array_ndims`
(or past `enum_type_name` when ndims=0), read one more byte as `identity_kind`.

**Compatibility rule:** Adding bytes at the end is the established pattern (same as `array_ndims`,
`enum_type_name`, etc.). Old readers stop before the new byte; new readers fall back to `None`
when the byte is absent.

## Edge cases

- [ ] `GENERATED ALWAYS AS IDENTITY` on a BIGINT column — must work (not just INT)
- [ ] `GENERATED ALWAYS AS IDENTITY` with OPTIONS clause — parsed without error, options silently ignored
- [ ] INSERT omitting the identity column entirely — auto-generates (not an error)
- [ ] INSERT with NULL into ALWAYS column — auto-generates (not an error)
- [ ] INSERT with NULL into BY DEFAULT column — auto-generates
- [ ] INSERT with explicit 0 into ALWAYS column — errors (0 is treated as explicit non-identity trigger)
- [ ] INSERT with explicit 5 into BY DEFAULT column — stores 5 (not an error)
- [ ] SHOW COLUMNS shows correct Extra for both kinds
- [ ] SHOW CREATE TABLE round-trips correctly
- [ ] Old `AUTO_INCREMENT` table: `identity_kind` reads as `None`, behavior unchanged
- [ ] Two consecutive inserts into ALWAYS column produce sequential values

## Performance budget

No new I/O. The identity_kind byte adds 1 byte to ColumnDef reads/writes; negligible.
