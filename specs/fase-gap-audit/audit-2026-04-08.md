# Auditoría completa — AxiomDB (2026-04-08)

## Resumen ejecutivo

Auditoría de 5 subsistemas: parser, executor, storage/WAL/MVCC, wire protocol, y catalog/FK/indexes.
Se encontraron **42 hallazgos** clasificados por severidad. Se proponen **3 subfases de gap closure**.

---

## HALLAZGOS POR SEVERIDAD

### CRÍTICO — Panics en producción (pueden crashear el servidor)

| # | Archivo | Línea(s) | Descripción |
|---|---------|----------|-------------|
| C1 | `axiomdb-sql/src/key_encoding.rs` | 206, 215, 224, 233, 242, 251 | `try_into().unwrap()` en decodificación de index keys. Index corrupto → panic |
| C2 | `axiomdb-sql/src/eval/batch.rs` | 146-157, 226-280 | `try_into().unwrap()` en BatchPredicate. Fila con encoding inválido → panic |
| C3 | `axiomdb-catalog/src/schema_constraints.rs` | 52, 53, 57, 67, 218-226 | `unwrap()` en deserialización de ConstraintDef y FkDef. Catálogo corrupto → panic |
| C4 | `axiomdb-storage/src/doublewrite.rs` | 207, 293 | `slot_count * DW_SLOT_SIZE` sin overflow check. Doublewrite corrupto → integer overflow → OOB read → panic |
| C5 | `axiomdb-wal/src/fsync_pipeline.rs` | 110, 151, 229, 251 | `.expect("poisoned")` en Mutex. Un panic en cualquier thread → cascading panics en fsync |
| C6 | `axiomdb-catalog/src/notifier.rs` | 106, 120, 130 | `.expect("poisoned")` en RwLock del catalog notifier |
| C7 | `axiomdb-sql/src/executor/agg_accum.rs` | 100, 108, 118, 125, 135, 150, 171 | `simple_arg.unwrap()` en acumuladores DISTINCT. Programáticamente construible sin arg |

## SUBFASES PROPUESTAS

### Subfase GAP-A: Hardening — Eliminar panics de producción

**Prioridad: CRÍTICA — hacer antes de cualquier otra implementación**

Scope: Reemplazar todos los `unwrap()` / `expect("poisoned")` en código de producción.

```
GAP-A.1: key_encoding.rs — unwrap → map_err(DbError::CorruptedIndex)
GAP-A.2: eval/batch.rs — unwrap → return default/skip row
GAP-A.3: schema_constraints.rs — unwrap → DbError::ParseError con contexto
GAP-A.4: doublewrite.rs — checked_mul + bounds check antes de slice
GAP-A.5: fsync_pipeline.rs — unwrap_or_else en Mutex (o PoisonError → DbError)
GAP-A.6: notifier.rs — mismo patrón que A.5
GAP-A.7: agg_accum.rs — validar simple_arg en constructor
GAP-A.8: exec_with_ctx.rs — refactor conn_txn checks (helper que retorna Result)
```

Esfuerzo estimado: **medio** (mecánico pero con tests de regresión)
Tests: cargo test --workspace debe pasar; agregar tests con datos corruptos para C1-C4

---

### Subfase GAP-B: MySQL wire compat crítica

**Prioridad: ALTA — necesario para ORMs**

```
GAP-B.1: UNION / UNION ALL — parser + executor (materializa ambos lados + dedup/append)
GAP-B.2: Column type wire codes — TINYINT(0x01), SMALLINT(0x02), MEDIUMINT(0x09),
          YEAR(0x0d), TIME(0x0b), DATETIME(0x0c) en datatype_to_mysql_type()
GAP-B.3: DECIMAL column type — almacenar como i128 con scale; CREATE TABLE + INSERT/SELECT
GAP-B.4: DATE column type independiente — days-since-epoch, no timestamp
GAP-B.5: Multi-table DELETE/UPDATE JOIN syntax — parser + executor
GAP-B.6: FK RENAME TABLE — actualizar axiom_foreign_keys al renombrar tabla
GAP-B.7: SHOW PROCESSLIST real — exponer conexiones activas desde handler
GAP-B.8: INTERSECT / EXCEPT — parser + executor (hash-based set ops)
```

Esfuerzo estimado: **alto** (UNION requiere cambios en parser+executor+wire)
Tests: wire-test.py con todos los escenarios; ORM smoke test

---

### Subfase GAP-C: SQL completeness + DDL robustness

**Prioridad: MEDIA — mejora significativa de compatibilidad**

```
GAP-C.1: Subquery in JOIN — FROM (SELECT) en posición JOIN ya funciona; wiring faltante
GAP-C.2: Composite FK (multi-column) — extender axiom_foreign_keys encoding
GAP-C.3: ALTER TABLE DROP/MODIFY COLUMN con index — auto-drop/rebuild index
GAP-C.4: ON DELETE/UPDATE SET DEFAULT — requiere default persistence (ya existe en 4.18e)
GAP-C.5: GROUP BY WITH ROLLUP — parser + executor synthetic NULL rows
GAP-C.6: ALTER AUTO_INCREMENT=N persistence — escribir en catalog
GAP-C.7: DROP INDEX not found → DbError::IndexNotFound (no NotImplemented)
GAP-C.8: Correlated subquery depth > 1 — substitution chain en analyzer
GAP-C.9: MySQL default collation case-insensitive en CompatMode::Mysql
GAP-C.10: COM_STMT_SEND_LONG_DATA validación de stmt_id
```

Esfuerzo estimado: **alto** (composite FK y subquery en JOIN son complejos)
Tests: integration tests por cada item + wire-test.py
