# Spec: 21.24 — ORM compatibility tier 2

Phase: 21 — Advanced SQL
Task: 21.24 ORM compatibility tier 2
Status: implemented

## Context

Phase 21 already closed several ORM-visible SQL gaps: `RETURNING`, `MERGE`,
MySQL DML variants, query hints, cursors, advanced acceptance coverage, and a
good portion of MySQL-style metadata interception in the wire layer. The
roadmap item for `21.24` says "Prisma and ActiveRecord connect; migrations
with RETURNING, GENERATED IDENTITY and deferred FK; document incompatibilities".

Two of those phrases point at still-open feature work outside this subphase:
`GENERATED ... AS IDENTITY` is still tracked under `24.1c`, and deferred /
`DEFERRABLE` foreign keys are still `21.16`. This task therefore must focus on
compatibility validation, targeted wire/metadata shims, and explicit
documentation of what already works vs what remains blocked.

## Goal

Establish a bounded tier-2 ORM compatibility baseline for Prisma and
ActiveRecord by validating connect + schema discovery + basic migration SQL on
the current engine, adding only the minimal compatibility shims needed to make
that baseline work, and documenting remaining incompatibilities precisely.

## Non-goals

- Implementing `GENERATED ALWAYS AS IDENTITY`.
- Implementing `DEFERRABLE INITIALLY DEFERRED/IMMEDIATE` foreign keys.
- Building full Prisma or ActiveRecord adapters.
- Guaranteeing that every migration generated by those ORMs will succeed.
- Reworking broad SQL semantics outside the minimum compatibility surface found
  by the audit.

## Behavior

### Public API

No new end-user SQL feature is required by default. This subphase may add
small MySQL-wire compatibility shims and documentation, but it should not
invent a new large SQL surface unless a concrete ORM probe requires it.

### Compatibility target

Tier 2 means:

1. Prisma and ActiveRecord can complete their initial connection /
   introspection probes without hitting obvious unsupported-connect failures.
2. Current AxiomDB SQL surface is sufficient for a bounded migration-style
   smoke that uses features already implemented here (for example:
   auto-increment / `SERIAL`, `RETURNING`, `SHOW FULL ...`, table metadata).
3. The repo explicitly documents which common ORM expectations still fail due
   to not-yet-implemented features such as identity columns and deferred FKs.

### Semantics

- Start from observed ORM-visible probes and metadata queries already
  documented in `docs/gaps-mysql-compat.md` and the wire intercept layer.
- Add targeted compatibility fixes only when they are:
  - directly exercised by Prisma / ActiveRecord connect-introspection paths, or
  - small migration-blocking metadata gaps that fit the compatibility scope.
- Prefer MySQL-surface compatibility shims over deep executor changes when the
  ORM only needs connect/introspection behavior.
- If a migration requirement depends on a missing major feature
  (`GENERATED IDENTITY`, deferred FK), the correct output of `21.24` is a
  documented incompatibility note plus a bounded smoke proving the rest of the
  flow works.

Potential in-scope shim areas if the audit confirms they are still missing:

- `SHOW FULL TABLES`
- `SHOW FULL COLUMNS`
- `SHOW TABLE STATUS`
- related metadata rows/columns expected by schema discovery

### Error / compatibility cases

| Case | Expected handling |
|------|-------------------|
| Prisma / ActiveRecord connect probe uses already-supported metadata query | succeeds |
| ORM probe hits a small missing metadata variant | implement the narrow shim if it fits `21.24` |
| ORM migration expects `GENERATED ... AS IDENTITY` | explicitly documented as blocked by `24.1c` |
| ORM migration expects deferred FK semantics | explicitly documented as blocked by `21.16` |
| Current engine behavior differs materially from MySQL/Postgres ORM expectations | document the incompatibility in phase docs / memory and keep the smoke bounded |

## Edge cases

- [ ] Connect/introspection path does not regress ordinary existing clients.
- [ ] Prisma-visible metadata queries succeed or are explicitly documented when
      blocked by out-of-scope features.
- [ ] ActiveRecord-visible metadata queries succeed or are explicitly
      documented when blocked by out-of-scope features.
- [ ] A migration-style smoke uses `RETURNING` / auto-increment / metadata
      paths that already exist today.
- [ ] Missing identity-column support is called out explicitly, not silently
      misrepresented as supported.
- [ ] Missing deferred-FK support is called out explicitly, not silently
      misrepresented as supported.

## On-disk format

No on-disk format changes are required for the compatibility baseline itself.

Compatibility rule: `21.24` should remain wire/parser/executor-surface work and
documentation unless a concrete small fix requires touching existing metadata
structures.

## Performance budget

| Operation | Target | Max acceptable |
|-----------|--------|----------------|
| New metadata/introspection shims | existing lightweight connect-path cost | no material regression in normal wire connect path |
| Compatibility smoke runtime | targeted and small | must stay practical inside `tools/wire-test.py` and crate integration tests |

## Dependencies

- Depends on current MySQL wire interception / SHOW support in `axiomdb-network`
- Depends on completed Phase 21 features such as `RETURNING`
- Depends on `docs/gaps-mysql-compat.md` as the current compatibility inventory
- Blocks: a clean Phase 21 statement of what ORM tier-2 support means today

## Open questions

- [x] `21.24` should not absorb `24.1c` identity columns.
- [x] `21.24` should not absorb `21.16` deferred FK semantics.
- [x] The right cut is compatibility validation + minimal shims + explicit docs,
      not large feature implementation under an ORM label.

## Done criteria

- [x] Spec/plan define `21.24` as compatibility validation plus minimal shims.
- [x] A bounded Prisma / ActiveRecord compatibility smoke exists in tests or wire harness.
- [x] Any small metadata/introspection shim required by the smoke is implemented.
- [x] `docs/progreso.md` / `docs/fase-21.md` document remaining incompatibilities
      around identity columns and deferred FKs explicitly.
- [x] `cargo test` for touched SQL/network compatibility tests passes.
